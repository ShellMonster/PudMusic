# 分层与子系统

> 原文在 `README.md`《代码怎么分层》《封面内存缓存》，以及 `AGENTS.md` §4 界面层第 3 条
> （两扇窗共用一份状态）那部分背景。

**什么时候用得上**：你要加一个新子系统（音频、网络、平台能力……）、或者你不确定某段
代码该放哪一层、或者你在排查「迷你窗和主窗显示不一致」。

---

## 依赖单向

**出处**：`README.md`《代码怎么分层》

反向一律禁止：

```
internal/ui/        → internal/app/ → internal/service/ → internal/platform/
   画界面              全部状态         解码、播放         平台差异
（只有这一层 import mygo/ui）

internal/licensing/  → 不 import 任何 internal 包（只读 go.mod 和模块缓存）
internal/platform/cmd/, internal/licensing/cmd/   → 生成用的命令行，不进运行时
```

**为什么这条单箭头很重要**：应用层**不认识界面**（`internal/app` 的包注释第一条），
而界面层是 import 应用层的那一边。所以「说一句话」那种语义（成功 / 警告 / 失败 / 普通）
不能住在界面层里——那样应用层 import 不到它。它住在 `internal/notice`：谁都能 import，
而自己不依赖任何东西。颜色是界面层的事（`internal/ui` 里的 `toastColors`），那里只说
「这句话是哪种」。

**什么时候用得上**：你在加一个包，想知道它该在哪一层、能不能 import 另一个。

## `main.go` 只做一件事

**出处**：`README.md`《代码怎么分层》（+ `internal/app` 的包注释）

**启动装配、窗口和运行时接线。**

`bootstrap.Assemble` 的第一阶段是 `platform.PinUserDataDir()`（见
[data-and-credentials.md](data-and-credentials.md)），然后创建 `app.App`，完成挂载，最后创建窗口并运行。

**什么时候用得上**：你在 `main.go` 里加逻辑——先问一句「这是状态、窗口，还是接线」。

## 两扇窗

**出处**：`README.md`《代码怎么分层》（+ `AGENTS.md` §4 §「界面层」第 3 条的背景）

窗口有**两扇**：

| 窗口 | 尺寸 | 位置 |
|---|---|---|
| 主窗口 | 1200×800（最小 900×560） | `internal/ui/shell_window.go` 的 `WindowOptions` |
| 迷你播放器 | 320×84 的透明置顶小窗 | `internal/ui/miniplayer.go` 的 `MiniWindowOptions` |

- 它们各有各的 `Shell`（一个外壳对一个窗口），但**播放状态是同一份 `app.App`**——所以
  界面上不会显示不同，**前提是改完状态之后挨着两扇窗都唤醒**（见
  [interface-pitfalls.md](interface-pitfalls.md)《唤醒》）。
- 迷你播放器开着的时候**主窗口是收起来的**，两个窗口**互斥**（Biu 也是这么干的）。
- 迷你窗是 `Panel` 语义：显示 / 聚焦给键盘，但**不激活应用**（票 #162）；`Transparent`
  必须配着自己画的背景，否则窗口在桌面上是隐形的。

⚠️ **以代码为准**：迷你窗是 `miniWidth = 320` / `miniHeight = 84`
（`internal/ui/miniplayer.go`）。旧版 README 的「代码怎么分层」那一节写过 320×100，
那是**过时的数字**（票 #357 已改成 320×84）——BMG-290 瘦身 README 时那一节整节删掉了，
所以**现在 README 里不再有这个尺寸**。代码里那些提到 320×100 的注释是另一回事
（那些是本票范围外的历史留痕）。

**什么时候用得上**：你在加第三扇窗、或者在改「迷你窗显示的内容不对」。

## 封面缓存与内存预算

**出处**：`README.md`《封面内存缓存》

启动时可以用环境变量 `BIU_IMAGE_CACHE_MB` 配置**内存**缓存预算，单位是 MiB
（1 MiB = 1024×1024 字节），接受 1–4096 的整数；未设置或无效时使用 32 MiB，无效值会写
一条日志。改后**重启**生效，主窗口和迷你播放器共用这份缓存。

代码里的默认值是 `internal/ui/widgets/imgcache/cache.go` 的 `DefaultMaxBytes`（32 MiB）。

| 预算 | 取舍 |
|---|---|
| 96 MiB | 保留更多已看过的封面，回滚时较少重新解码。 |
| 32 MiB（默认） | 减少常驻图片，回滚时更容易需要读盘、解码。 |
| 16 MiB（或更小） | 更积极淘汰，反复滚动时更常重新加载，首帧可能变慢。 |

96 → 32 MiB 在 BMG-263 的原 PNG 探针中测得**堆峰值 415.0 → 298.8 MB**（约省 116 MB）；
这不是所有图片格式的固定收益。

```sh
BIU_IMAGE_CACHE_MB=32 go run .
# 已安装的 macOS 应用先退出，再从终端启动：
BIU_IMAGE_CACHE_MB=32 /Applications/BiuGo.app/Contents/MacOS/BiuGo
```

### 内存未命中时先读磁盘缓存

磁盘也未命中才重新下载，因此**网络代价取决于磁盘命中率**。

这只是**图片缓存**的预算：正在显示的图片受保护，可以暂时超额；它**不限制整个进程的内存**。

### 长期没人要的封面会放掉像素（票 #673）

一张封面**连续 `DefaultReleaseAfterFrames` 帧（默认 120）没被任何一块界面要过**，
缓存就把它那个 `*ui.Bitmap` 整个放掉（像素和 mipmap 链跟着被 GC 回收），条目本身留着
记「下次要重新解」；界面再滚回来时它从**磁盘缓存**重新解码，一帧占位之后恢复成图。

- **判据是帧号，不是墙钟**：`Cache.BeginFrame` 每帧推一次，和「画面上正画着」那几张
  用的是同一个号。窗口不再画帧的时候这一档**不跑**——没有帧就没有「这一帧画着谁」，
  那时候放掉的可能正是用户眼前那张。
- **显示中的永远不放**：`visibleFrames`（4 帧）之内，以及每一帧都被 `Get` 到的那几张
  （画面上每一格每帧都会问自己的图），`drawn` 一直是新的，永远轮不到释放。
- **放掉之后账同步归零**：`UsedBytes()` 只算真的还挂着的像素，不会出现「账上占着、
  实际已经放了」。
- **重新解码沿用同一条加载链路**（磁盘优先 → 解码 → 缩放 → 记账），所以尺寸档位、DPR、
  裁剪、圆角、失败态全都不变；代价是**一次读盘 + 解码**（672×378 WebP 约 15~37ms，
  在后台解码 worker 上），界面上先出现一两帧占位。
- 只放 **CPU 那份 RGBA**；GPU texture 由框架自己按「连续 240 帧没画过」清扫。
- 阈值、条数上限和完整理由在 `internal/ui/widgets/imgcache/release.go`；
  重新解码次数由 `Cache.ReleaseStats()` 报（**只给测试和诊断**，生产不读）。

**什么时候用得上**：你在查「滚很久之后内存不回落」「滚回去封面要等一下」，或者你要动
`ReleaseAfterFrames` / `MaxReleased`。

### 解码路径

- 普通大 PNG（非交错、8 位 RGB/RGBA）**逐行解码**；
- 基线 JPEG（灰度或 YCbCr，单扫描）**只保留两行 MCU 块**；
- 两者都按原来的 ApproxBiLinear 算法缩到最长边 768，**保留相同像素**，避免临时分配
  整张原图；
- 渐进式 JPEG、RGB/CMYK JPEG、其他格式及特殊 PNG 仍走标准解码器；
- EXIF 只有元数据或方向为 1 的 JPEG 也会缩放；真正需要旋转 / 翻转的 JPEG 继续由框架摆正，
  保留原尺寸。

**什么时候用得上**：你在查「内存占用高」「首帧慢」「封面要重新加载」，或者你要改图片
解码 / 缓存的预算。

## 回归证据是代码，不是文档

**出处**：`AGENTS.md` §9《技能文档与两份不在仓库里的东西》「回归证据」那一条

SPEC 那张「每个阶段要留下什么证据」的清单在 `internal/evidence`——它是一个 Go 包，
`var Items = []Item{…}` 那一张台账。

- **加一条证据、加一个测试或者给测试改名，都意味着要同步改那张表**；不改的话它自己那条
  测试会红，**那正是它该做的**。
- ⚠️ 那张台账现在三千多行，**行多不代表耦合多**——它是台账不是逻辑，拆了反而破坏
  「一张台账」这个概念（见 [git-and-workflow.md](git-and-workflow.md)《文件怎么组织》）。

**什么时候用得上**：你要加一条证据、或者改了测试的名字。
