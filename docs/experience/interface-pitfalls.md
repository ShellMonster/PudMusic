# 界面层：静默出错的地方

> 原文在 `AGENTS.md` §4《静默出错的几条铁律》§「界面层」与 `README.md`《踩过坑的规矩》。

这个框架（MyGo）**不写这些坑的文档**——它们全是踩出来的。踩中任何一条的**症状都是
静默的**：不报错、不崩溃、不打日志，界面上只是悄悄不对。所以全靠下面这些约定兜着，
而不是靠测试告诉你。

**什么时候用得上**：你要动 `internal/ui/` 里的绘制、输入处理或 view 生命周期；或者你在
排查一个「界面不动了 / 点了没反应 / 选中的变成了旁边那一个 / 主题跳回系统色」这类
症状——症状没有报错可查，正是因为它们全在这一页里。

---

## 主题色

**出处**：`AGENTS.md` §4《静默出错的几条铁律》§「界面层」第 1 条

**`SetTheme` 必须每帧在 view 最开头调。**

框架每帧开头把主题重置成跟随系统那一份，放到切换按钮的回调里只调一次会被**静默丢掉**
——主题悄悄跳回系统色。

- 入口是 `internal/ui/theme.go` 的 `ApplyTheme`；**别的地方不许直接调 `c.SetTheme`**。
- `ApplyTheme` 是每帧都跑的那一份，所以它放在 view 的第一行。

**什么时候用得上**：你在动主题、配色、皮肤预设，或者现象是「切了主题但下一帧就跳回去」。

---

## panic

**出处**：`AGENTS.md` §4 §「界面层」第 2 条

**view 里 panic 会穿透事件循环杀掉整个进程。**

框架的 `Dispatch` / `drain` 都**没有 recover**，所以 view 里的 panic 会一路穿透 Cocoa
事件循环，把整个应用带走。

- 每个页面 view 外面包一层 `ui.Guard`，底层是 `internal/ui/guard.Wrap`。
- **行级的和页级的两道不重复**，别包两次（两层都包会让同一个 panic 被吞两次，
  错误信息也丢）。

**什么时候用得上**：你在加一个新页面 / 新控件的 view，或者你在查「应用莫名其妙没了」。

---

## 唤醒

**出处**：`AGENTS.md` §4 §「界面层」第 3 条（+ `README.md`《踩过坑的规矩》2）

**后台投递完状态必须叫醒界面。**

即时模式是按需绘制，只投递不唤醒，界面永远停在旧帧。

- 走 `ui.Services.Invalidate()`（`internal/ui/wake.go`）。
- **而且要挨着每一扇窗叫醒**——只叫醒主窗口的话，迷你播放器停在旧内容（实测）。
- 改状态用 `Window.Update(func)`，只刷画面用 `Invalidate()`；
  **`Window.Update(nil)` 会 SIGSEGV，进程直接死。**

### 窗口看不见时那一帧会被这一扇窗自己丢掉

这是**设计**，不是 bug（`wakeHandle` + `presence`，票 #156）：

- 在放歌的时候 `App.tick` 每 50ms 叫醒每个窗口一次。收在后台的那扇窗把这一帧丢掉，
  不丢的话就是风扇和电池。
- 丢掉的只是**绘制**，状态照常落；窗口回来时 `Shell.noteWindow` 用 `invalidateNow`
  补一帧，画出来就是此刻的样子。
- 所以「逐窗口叫醒」的那一层（`App.AddWake` / `App.AddLocalWake`）**不要**改成
  「只叫醒看得见的窗口」——看不见这件事只有每个窗口自己知道（迷你窗就不看焦点）。
- 全新一帧里要判可见性的动画走 `hover.SetFrameVisible`（`Shell.View` 每帧设）。

**什么时候用得上**：你在写后台任务（下载、取流、扫本地音乐），或者现象是「后台明明
成功了，界面还是旧的」/「迷你窗内容不跟着更新」。

## 行 key

**出处**：`AGENTS.md` §4 §「界面层」第 4 条

**动态列表的行必须给稳定且唯一的 key。**

默认身份是「父 ID + 兄弟序号」，在前面插入一行会让后面所有行的状态整体错配——症状是
「**选中的那一首变成了旁边另一首**」，而每一行的字都是对的。

**什么时候用得上**：你在写一个会插入 / 删除 / 重排的列表（队列、收藏夹、搜索结果、
下载记录）；或者现象是「点了一首，播放的是隔壁那首」。

---

## 拖动

**出处**：`AGENTS.md` §4 §「界面层」末尾《拖动状态用 `Pressed()`》+ `README.md`《踩过坑的规矩》拖动两条与「别拿 `Dragged()` 的位移累加」

三个 API 各管一件事，**用错都不报错、只是拖不动**：

| API | 报的是什么 | 陷阱 |
|---|---|---|
| `Pressed()` | 元素当前被按住 | **多一条「指针仍在控件框内」的条件** |
| `Dragged()` | 「按着没有」+ 位移 | 位移**每帧结束才清掉**，一帧里 view 跑好几遍 |
| `Dragging()` | `Drag` / `Draggable` **两套机制** | **对普通控件永远是 false** |

- **`Dragging()` 不要用来判普通控件的拖动。** MyGo 自带的 `examples/timeline` 那一处
  判断就是失效的，别照抄。
- **`Pressed()` 在窄把手上会卡住**：它要求「指针仍在控件框内」，所以一条 8 像素宽的
  拖拽把手用它只能拖 16 像素就卡住（指针往左挪 9 个像素就出框了，当场变 `false`，
  见 `internal/ui/sidebar.go` 的注释）。这种把手要用 `Dragged()` 判按着没有、再用
  `PointerPosition()` 取绝对位置。侧栏那条 8 宽的把手就是这么做的
  （`internal/ui/sidebar.go`）。
- **别拿 `Dragged()` 的位移累加。** `dragX` 要到一帧结束才清掉，而一帧里 view 要跑
  **三遍**（`runtime.go` 的 `for pass := 0; pass < 3`），每一遍读到的都是同一个位移，
  累加起来就是**拖快好几倍**。取绝对位置就没有这个问题。

完整的两个坑写在 `internal/ui/sidebar.go` 和 `internal/ui/playbar.go` 的注释里。

**什么时候用得上**：你在加滑块、拖拽把手、裁剪框、可拖动的列表项；或者现象是
「拖不动」「一拖就飞」「点一下就松手」。

## 测试里的钟

**出处**：`README.md`《版本》「v0.5.5 起必读」

**MyGo v0.5.5 起，`ui.Tester` 的钟站着不动了。**

动画、`Context.After`、双击判定全走那只钟，只有测试自己调 `tt.Advance(d)` 它才走。

所以「循环 `tt.Frame()` 等动画停下来」这类辅助函数会**静默失效**——钟不走，动画永远
停在第一帧，而「连着几帧不动」读到的恰恰是「不动」，于是它判定「停了」放行；接下来
`tt.Click` 照着窗口外的坐标点下去**照样返回 nil，什么也没发生**。

**症状是「点了没反应」，不是「等不到」**，很容易误判成控件坏了。

要等动画就走两步：**推钟**（`tt.Advance`）+ **问 `tt.FramePending()`**（view 还在要帧吗），
**不要数帧数**。照这么写的例子见 `internal/ui/settings_test.go` 的 `settleSettingsPage`；
框架自带的 `internal/ui/shelltest_test.go` 里的 `waitFor` / `waitFrames` 也是这个思路。

**什么时候用得上**：你在写或改 `internal/ui/` 下的测试，尤其是任何「等动画 / 等布局
稳下来 / 等某一帧画出来」的用例。

## 小结：这几条的共同形状

**出处**：本目录新增（把上面几条并成一张表）

| 坑 | 症状 | 静默吗 |
|---|---|---|
| 主题色放错位置 | 主题跳回系统色 | 是 |
| view 里 panic | 应用整个没了 | ❌ 会崩，但**不给你栈** |
| 只投递不唤醒 | 界面停在旧帧 | 是 |
| 只叫醒主窗口 | 迷你窗停在旧内容 | 是 |
| `Update(nil)` | 进程 SIGSEGV | ❌ 会崩 |
| 行 key 不稳 | 选中的变成旁边那首 | 是 |
| `Dragging()` | 拖不动 | 是 |
| `Dragged()` 位移累加 | 拖快好几倍 | 是 |
| 数帧等动画 | 点了没反应 | 是 |

⚠️ **「静默」这一列全是这一页存在的理由**：它们不会在 CI 上红，也不会在评审里被
看出来，只会在用户手上出现。所以它们既在代码注释里，也在这里。

**什么时候用得上**：你在给这一页加新的一条坑，或者你在判断「这个症状会不会是这一页里的某一条」——先对着这张表扫一眼。
