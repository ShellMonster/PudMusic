## 四个名字

**出处**：`AGENTS.md` §5《不可协商的项目不变量》第一条

**显示名、bundle id、钥匙串服务名、用户数据目录名是四件互不相干的事。**

| 名字 | 现在的值 | 能不能改 |
|---|---|---|
| 显示名（`mygo.json` 的 `name`） | 2026-10 从 `Biu MyGo` 改成 `BiuGo`，2026-10-26 又改成 `布丁音乐` | 能改（就是改应用名） |
| bundle id（`mygo.json` 的 `identifier`） | `io.github.shellmonster.biu` | **不能**——bundle id 变了会影响 macOS 的隐私授权 |
| 钥匙串服务名 | `com.biu-go.biu-mygo.login` | **不动**（登录态已经不在钥匙串里了，见下） |
| 用户数据目录名 | `PudMusic`（旧目录 `Biu MyGo` 自动迁移） | **不动**——见《用户数据目录》 |

⚠️ **2026-10-25 之后登录态不在钥匙串里了**（在用户数据目录下的
`credentials/session.json`，见 `internal/app/credentials_file_darwin.go`）——那个服务名
**不再有任何用途**，代码里也没有迁移 / 清理。所以现在「**登录态跟着哪个名字走**」这件
事**由用户数据目录名决定**；目录从 `Biu MyGo` 迁到 `PudMusic` 时，登录态跟着整个目录一
起被 `os.Rename` 过去。

**什么时候用得上**：你在改应用名、bundle id、或者在查「为什么登录态 / 设置跟着某个名字
走」。

## 用户数据目录

**出处**：`AGENTS.md` §4 §「启动与生成物」第 9 条（+ `README.md`《踩过坑的规矩》8）

**用户数据目录的名字不跟显示名走，但跟着项目定名走。**

应用 2026-10 从 `Biu MyGo` 改名成 `BiuGo`，后来定名「布丁音乐」（`PudMusic`）。而
`mygo.App.Path(mygo.PathUserData)` 默认是 `os.UserConfigDir()` **拼应用名**
（`mygo` 的 `paths.go`：`case PathUserData: return filepath.Join(dir, App.Name())`）。

`internal/platform/datadir.go` 的 `PinUserDataDir()` 干两件事：

1. **把目录钉在 `LegacyUserDataDirName = "PudMusic"`**——而不是框架默认的应用名
   （`布丁音乐` 或 `PudMusic`，看构建参数）。钉死让「显示名再改」不再动数据目录。
2. **把旧目录 `Biu MyGo` 自动迁移过来**：旧目录在、新目录不在时，整个 `os.Rename`
   到 `PudMusic`。新旧都在就不动旧的——可能是迁过一次之后又有东西写回去，也可能是
   用户自己放的。

### 为什么搬，而不是继续钉 `Biu MyGo`

`datadir.go` 顶上那一节记着完整的取舍，摘要：

1. **搬目录用 `os.Rename`，不是逐文件复制。** `os.Rename` 是同分区原子的：要么整个过去、
   要么原地不动，**没有「搬一半」的中间态**——那正是「错了就静默丢数据」的那个错法。
2. **迁失败退回旧目录并报出来，不用空目录开起来。** 跨设备、权限不够、目录被占——`PinUserDataDir`
   会 `mygo.App.SetPath` 回旧的 `Biu MyGo`，把错误**返回**给 bootstrap 记日志。
   这是从 `internal/app/migrate.go` 那一版的错里长出来的教训（那个文件后来整文件删掉，
   逻辑并到 datadir.go）。
3. **目录名和应用名一致，Finder 里不再混。** 用户进 `Application Support` 看到的就是
   `PudMusic`，和正在用的应用对得上号——不用记「`Biu MyGo` 其实是新应用的数据」。

### 调用时机

`bootstrap.Assemble` 的第一阶段调用 `PinUserDataDir()`，它排在 `app.New()` 与所有 `Mount*` 之前：

- 必须排在所有 `mygo.App.Path(mygo.PathUserData)` 之前；
- 「**读不到设置**」的默认处理是**安静地按第一次运行开起来**——晚一步的症状是
  「**设置一直存不住**」，而不是任何一句报错。

### ⚠️ 已经有人钉过就别再钉

`PinUserDataDir` 开头会先查一次「是不是已经被钉过了」：判据是 `mygo.App.Path` 返回的目录名
最后一段**是不是应用名**——是应用名说明是框架默认（没被钉过），否则就是有人钉过了。
E2E 那一轮（`automation_e2e.go`）就靠这个把数据目录挪到临时目录，**不抢用户正在跑的
那个应用的单实例锁**。

**什么时候用得上**：你在改应用名、在动设置 / 缓存的落盘位置、或者在排查「数据不见了」。

## 登录态

**出处**：`README.md`《已知边界 → 登录》（+ `internal/app/credentials_file_darwin.go` 的包注释）

### 为什么不在钥匙串里了

用户 2026-10-25 报的现象是「**现在每次打开都需要钥匙串授权**」。

查清之后（BMG-261 / issue #473 的调研），根因不是「钥匙串反复盘问」，而是：

- 钥匙串认的是**代码身份**，而 ad-hoc 签名的 designated requirement 认死那**一个字节级
  二进制**（`cdhash H"…"`）；
- 每一项的访问判定最终落在**分区列表**上，而分区 id 只有三档是稳的：`apple-tool:` /
  `apple:` / `teamid:`；
- `teamid:` 只给 Developer ID / Mac Development / Mac Distribution / MAS / TestFlight，
  **ad-hoc 和自签证书一律落到 `cdhash:` 那一档**——每重新构建一次换一次，钥匙串就认不出
  这是谁，弹一次框要授权。

那一项的分区列表里现在堆着 **22 条历史 cdhash**，那就是 22 次「重新构建 → 重新授权」的
化石记录。

### 落在哪

| 平台 | 位置 | 保护 |
|---|---|---|
| macOS | `<用户数据目录>/credentials/session.json` | 目录 700、文件 600 |
| Windows | `<用户数据目录>/credentials.dpapi` | DPAPI 加密 |

旧的钥匙串那一项**不迁移、不清理**：软件还没发版，没有别的用户的老数据。本机上留着的
旧条目，想删就手动 `security delete-generic-password -s com.biu-go.biu-mygo.login`，
然后重新扫码登录一次。

### ⚠️ 这一条是**安全倒退**，说在前面

钥匙串那一层提供的保护是「**别的程序读不到**」。改成文件之后没有了：**同一台机器上、
同一用户下的任何进程都能读这个文件**（权限位 600 拦的是「别的用户」，**不拦同一个用户
的别的进程**）。

真正少掉的那一层因此是「**钥匙串会在你授权的时候提醒你一下**」，而不是「别的程序偷不到」
——后者在同一个用户下本来也拦不住。

另一处差别：钥匙串里的凭据**跟着账号走**（换机、重装系统后登录同一个 Apple ID 就带着），
文件不会——**换机要重新扫码登录**。Windows 那侧一直是 DPAPI 加密的文件，本来就不弹框，
**没动**。

### 为什么文件权限仍然要紧

600 + 目录 700 挡的是「**别的用户**」（共享机器上的另一个人）。这一层的意义和钥匙串的
「别的程序读不到」不同，但也不是零——它挡的是「另一个用户账号下的程序」，以及「别人拷走
你的磁盘镜像」。

⚠️ **权限被放宽了要能被发现**（`checkPermissions`）：权限位不是保险栓，是**提醒**——被改成
644 之后**没有任何东西会报错**（它照常读照常写，登录态照常能用，只是别人也能看了），所以
这一层自己得会喊：每次读它都查一遍，发现组 / 其他用户有权限就**当场收回 600**，并在
日志里记一笔。

**收回权限不会弄丢登录态**——内容照常读出来，登录态照常在。自己验：
`chmod 644 "$HOME/Library/Application Support/PudMusic/credentials/session.json"` 之后启动
应用——**登录态不会丢**，而 `ls -l` 会看到权限已经变回 600，那就是「被发现」的证据。

**什么时候用得上**：你在动登录 / 登出、凭据的读写、或在排查「掉了登录 / 权限变了」。

## 什么时候该写兼容逻辑

**出处**：`AGENTS.md` §5《不可协商的项目不变量》「别为老状态写兼容逻辑」那一条

**还没发版给别的用户用过，别为「我们自己的老状态」写兼容逻辑。**

默认口径：老的**外观**、老的**目录**、老的**设置值**、老的**测试期望**——**改了就是改了**，
不迁、不兜底、不留双份。

> **判据一句话：要兼容的是「别的用户的老数据」吗？不是 ⇒ 别写兼容。**

后果：**改动不需要迁移步骤、不需要双份格式、不需要兜底分支**；**老的那份数据直接作废**
（用户自己的老数据也作废——反正就他一个人，重新登录、重新导一次就完了）；**测试要对着
新样子写**，不要为了保住老的断言把新方案改回去。

### ⚠️ 下面这三样不是「兼容逻辑」，是另外三件事，照旧留着

1. **配置文件导入 / 导出**——设置页支持把不含凭据的配置 JSON 保存到文件，或从文件并入设置；
   不再读取本机 Biu 数据目录，也不自动搬运快捷键、歌词和下载记录。
2. **用户数据目录自动迁到 `PudMusic`**——那是**他自己**的数据（登录态、设置、歌词缓存、
   下载记录、历史），不迁他**自己**升级就丢。旧目录 `Biu MyGo` 留着不动（`os.Rename` 失败
   时也退回旧的并记日志），不替他做主。
3. **登录态本身**——那也是**他**的。它现在落在用户数据目录下的 `credentials/session.json`
   （macOS，权限 600）或 `credentials.dpapi`（Windows，DPAPI 加密）；钥匙串那一项
   **不迁移、不清理**，本机残留的自己手动删。

**什么时候用得上**：你在设计一个「改名 / 改格式 / 改默认值」的改动，正要写
`if oldVersion { ... }` 的时候——先回来读这一段。

## 别打真 B 站

**出处**：`AGENTS.md` §6《别打真 B 站》

凭据后端里是**用户真实的登录态**（见上）。收藏、点赞、播放记录上报都是**写操作**，写的是
那个账号。

- 验收和测试**一律走 HTTP fixture**（假 B 站），不要连真网。这一条不是洁癖：**封号代价
  远高于少验几条**，而 fixture 式的失败**只是测试红**，真网的失败是**账号上的垃圾数据**。
- 真接口的兼容性（参数集对不对、B 站收不收）**单独立项做真机回归**，别塞进功能票里顺手做。

**什么时候用得上**：你要写新接口的测试、或者在排查「本地跑测试会不会动到我的账号」。
