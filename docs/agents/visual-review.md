# 视觉审查怎么做

> 原文在 `AGENTS.md` §1《UI 票的验收必须有一次「视觉审查」》。

**纪律本体**（凡是动了界面「摆布」的票，验收里必须有一次视觉审查）在 `AGENTS.md`。
这份是**细则**：怎么比、怎么量、留下什么。

**什么时候用得上**：你在一张 UI 票上，要交出图并做审查那一步。

---

## ① 跟什么比

**出处**：`AGENTS.md` §1《视觉审查》①

**票面里必须写明是哪一样**，不许只写「对着上游看」：

- **上游 Biu 的对应页面**：源码取法见
  [`docs/experience/upstream-biu.md`](../experience/upstream-biu.md)《上游源码与截图怎么取》。
  **数值以上游源码为准**（`DESIGN.md` 就是这么来的）。上游 README 里的实图在
  `screenshots/`，**只有六张而且是旧版的**——**没有对应图就比源码，别去找不存在的
  截图**。
- **用户给的参考图**（用户 2026-10-25 那种截图）。
- **`DESIGN.md` 写明的那一版**：`DESIGN.md` 里已经拍板的数值（间距、圆角、列宽）。

**什么时候用得上**：你在一张 UI 票上定「拿什么当尺子」。

---

## ② 比什么

**出处**：`AGENTS.md` §1《视觉审查》②

五项，一项一项过；**间距要量，不要目测**：

- **布局**：哪一块在左 / 右 / 上 / 下，哪一块是容器，谁跟着谁走。
- **间距**：块与块之间多少。**用 F12 检查器的 box model 量**，别拿眼睛估。
- **层级**：哪一层压哪一层（浮层、蒙版、悬停层）——压错了图上是「不对」，不是报错。
- **密度**：一屏几行几列。
- **对齐**：边对不对齐、基线对不对齐。

**什么时候用得上**：你实际在做审查那一步。

---

## ③ 留下什么

**出处**：`AGENTS.md` §1《视觉审查》③

收尾说明里**逐条写差在哪儿**：

- ✅ 「关注页卡片：横向列间距 16（与上游一致）；**纵向行间距原为 0，上游
  `ROW_GAP = 16`** —— 已改」
- ❌ 「已出图，已做视觉审查」——**这一句不算数**：它没给出任何能核对的东西。

**什么时候用得上**：你写收尾说明的时候。

---

## ④ 不合格就继续改

**出处**：`AGENTS.md` §1《视觉审查》④

**审查是改之前的一道门，不是改之后的报备**：查出差异 → 改 → 重新出图 → 再审，直到五项
都对上。**不许「先交上去、评审再说」。**

**什么时候用得上**：审查查出差异之后。

---

## 逐像素比这件事

**出处**：`AGENTS.md` §1《视觉审查》末尾那个 ⚠️

⚠️ **不要要求逐像素比。** 出图本身不确定：同一份代码两次出图有几十张会不一样（字体
hinting、抗锯齿的随机相位，见 `internal/ui/ticket319_shot_test.go` 顶上那段）。

要比像素得**先跑两遍 HEAD 当对照**——那是另一回事，**视觉审查不查那个**。

**什么时候用得上**：有人在评审里要求「和上游逐像素一致」的时候。

---

## 一次真实的翻车（票 #418）

**出处**：`AGENTS.md` §1《视觉审查》开头那个 ⚠️（票 #418 / #479）

这张票是「视觉审查」这道门存在的理由：

关注页的 UP 主卡片**出图了、票也过了**，用户看一眼就发现**行与行之间贴死了**——列与列有
16 的缝，**纵向一格没有**。

那张票的验收标准里已经写着「间隙对着上游核过」，可**没人按「间距」这一项去量**——只对着
图扫了一眼，于是上游的 `ROW_GAP = 16`（**那是行间距**）被当成了格子之间的缝。

后来票 #479 修的。

⇒ **下面这几步就是当时缺的那道门**：把「跟什么比」写进票面、五项一项一项过、间距用
box model 量、把差在哪儿逐条写进收尾说明。

**什么时候用得上**：你怀疑「出图了 = 审过了」的时候。
