> 原文在 `AGENTS.md` §1《验收命令》、§2《测试结果只在机器不忙的时候算数》，以及
> `README.md`《怎么测》。

这份是**细则**：规矩本身（不许做什么）留在 `AGENTS.md`，这里写的是「怎么做、为什么、
有哪些坑」。

**什么时候用得上**：你要跑测试、判一条测试红是真的回归还是机器忙、或者你在加一条界面
测试。

## 测试分三层

**出处**：`README.md`《怎么测》

都不需要开窗口：

```sh
# 界面层：用 MyGo 的 Tester，view 不需要真窗口就能点、能拖
go test -v ./internal/ui/

# 业务层与解码：真解码器、真播放器，只是没有声卡时不出声
go test -v ./internal/app/ ./internal/service/audio/

# 打包层：图标尺寸集、第三方许可清单与实际构建依赖对不对得上
go test -v ./internal/platform/ ./internal/licensing/
```

音频相关的断言都只看**时间和位置**，不依赖「听得见」，所以在没有声卡的机器上也跑得过。

**什么时候用得上**：你在决定跑哪几个包。

## 验收命令

**出处**：`AGENTS.md` §1《验收命令》

```sh
go build -trimpath -p 4 ./... && go vet -trimpath -p 4 ./... && go test -p 4 $(go list ./... | grep -v '/internal/ui$')
```

### 编译缓存与 `-trimpath`

**`-trimpath` 是为了让编译缓存跨 worktree 命中。** 本板子上每个 agent 有自己的
worktree，源码所在的**绝对路径每个 worktree 都不同**——而 Go 的编译缓存 key 里带着
「包所在目录」，路径一变，同一份源码在另一个 worktree 就是**另一个 action**：于是 N 个
worktree 各编一遍、各存一份（实测：内容只差 1 个文件的两个副本，第二个要重编 **38** 个
包；每多一个 worktree 缓存多占 **41 MB**）。

`-trimpath` 把产物里的源码路径换成 **module 路径 + 相对路径**，路径不再进 key，缓存就能跨
worktree 共享（实测：38 → **4** 个包，41 MB → **0.85 MB**）。

⚠️ **三个硬条件，踩了更糟**：

1. **`test` 那一步不带 `-trimpath`**（票 #275 定下的口径，**别自己给 test 加上**）。
   `-trimpath` 之下 `runtime.Caller` 给的是 **import 路径**而不是文件系统路径，靠它定位
   文件的测试会红——`internal/ui/widgets/space` 那一处已经改成不依赖编译期路径了
   （票 #275），但 `widgets/scale`、`widgets/leading`、`widgets/scrim` 三处还是老写法
   （`#276` 带进来的），所以**整仓的 `go test` 现在都不能带**。
2. **不许用 `GOFLAGS=-trimpath`**——它对**所有** go 子命令生效（包括 `go test`），同样
   打红。**只能写进命令行。**
3. **所有 agent 必须一致**——半开半开会让缓存**翻倍到 518 MB**，比现状更糟。所以改这条
   命令的票必须**在同一个提交里**改完 `AGENTS.md` + `DESIGN.md` + 全部 open 票面；
   **板子自己的 check 命令也是一处**（`herdr-projects set check.command '…' --repo
   Biu_MyGo`）——它每个票都跑一遍，不改就等于板子一直在半开半开。

### `-p 4` 是限并发用的

这台机器主人自己也要用，别把它调大、别去掉（并行度拉满会跟界面抢 CPU，机器一卡，界面
测试自己也会飘）。

### 默认不跑 `internal/ui`

那是**界面行为**测试：一轮 62~298 秒，是全套里最贵的一块，而且它绿只证明画面没坏、
不证明别的什么。这台机器主人自己也要用，整包跑界面测试会把机器占满——界面测试自己都会
飘（见下面《已知会飘的那几条》），两边都不作数。

**动了界面行为，就只跑自己改的那几处**：

```sh
GOGC=10 go test ./internal/ui/ -count=3 -timeout 5m -run '你改的那几个用例名'
```

`-run` 里写这次动到的用例名（改了哪个 widget 就写哪个）。⚠️ **不要整包跑
`./internal/ui/`**——整包扫描是一次性排查手段（那张票叫「排查：哪些测试天生会飘」），
不是每票的验收项。

⚠️ **碰到了界面行为就必须跑上面那条 `-run`**，不能拿「默认不跑」当借口不跑——
`internal/ui` 是唯一一个「编译得过、绝大部分测试也过、但行为已经变了」的包，而框架改
界面行为**不改任何签名**。实在跑不动就在收尾说明里写清哪几处没验。

`internal/ui` 是唯一一个「编译得过、绝大部分测试也过、但行为已经变了」的包——它验的是
界面行为，而框架改界面行为**不改任何签名**。别只看最后一行有没有 FAIL，逐个包看 `ok`。
**它是默认不跑的**，所以它绿不绿只在你**亲自跑了它那几处**的时候才算数。

### 不带 `-race`

全量 `-race` 在这台 10 核机器上要十几到二十分钟（长板是 `internal/service/audio`、
`internal/service/audio/flacdec`、`internal/platform`），放进验收命令会让**每一张票**的
评审都跑到超时。曾经有一批票的验收行写着带 `-race`，agent 照着跑，评审全被拖死。

**票面写什么就照什么改，不要照抄旧行。** 真要查并发就单独挑那几个包跑 `-race`，不要
整包。

**什么时候用得上**：你要跑验收、或者你在改这条命令（改它的代价见上面《编译缓存与 `-trimpath`》）。

## 跑测试的几条口径

**出处**：`AGENTS.md` §2《测试结果只在机器不忙的时候算数》的前半段

- **不要用固定帧数 / 固定毫秒当判据。** 机器慢一点就飘，而飘的时候和被测的逻辑一点
  关系都没有——分不出来的那一次会被当成回归去查半天。等条件用现成的两个
  （`internal/ui/shelltest_test.go`）：`waitFor` 等后台写进状态的条件，`waitFrames` 等
  view 把它收进画面的条件。两者都循环到条件成立为止，里面的 deadline 只是「永远等不到」
  的保险，不是时间预算。
- **要等动画走完就推钟**：`tt.Advance(d)` 配 `tt.FramePending()`，不要循环 `tt.Frame()`
  数帧。框架的钟站着不动（详见 `docs/experience/interface-pitfalls.md`《测试里的钟》），
  数帧那种等法会**静默失效**：不报错、不超时，直接放行，于是后面每一次点击都按在旧坐标
  上。症状是「点了没反应」，不是「等不到」。
- **低负载下绿不算修好。** 这套测试在 load 9~10 时会飘，load 8 以下才作数。判「飘红是不
  是真 bug」之前先看一眼机器负载。
- **整包扫描前先看磁盘。** 这台机器是**共享**的：别的 agent 在编译、写盘，用户的应用
  也在写，可用空间在 **2.3 GB ~ 104 GB** 之间摆动（go 的编译缓存本身就有 7.5 GB）。
  写满时 `t.TempDir()` 建不出来，测试会红在一条**和改动毫无关系**的用例上，报错是
  `testing.go:1579: ... no space left on device`，而测试体一行没跑（`0.00s`）——**那不
  是回归，是磁盘满**。跑整包之前先 `df -h /System/Volumes/Data`，**可用空间低于 5 GB 就
  别跑**（等一会儿，或者跟人商量怎么腾空间——但**不要自己去清编译缓存**，见下面那条）。

  `internal/ui` 里有一道自动护栏（`internal/ui/diskguard_test.go`）：空间不足时**一条测试
  都不跑**，并把「磁盘空间不足」打在 stderr 上、**退出码非零**——`go test` 对失败的包会
  把这段输出原样打出来，所以它**不会被误当成「跑过了」**。看见那几行字就是磁盘的事，别
  去查界面代码；确实要硬跑就设 `BIU_TEST_ALLOW_LOW_DISK=1`（风险自负）。

- **不许清编译缓存。** `go clean -cache`、或者把整个 `~/Library/Caches/go-build` 目录删
  掉，这类命令**任何 agent 都不许自己跑**。原因实测过：编译进行中并发跑一次
  `go clean -cache`，那个 agent 的 **754 个编译成果当场消失，而它自己 exit 0 毫不知情**
  （事后缓存里什么都没有），重建代价 **151 秒/agent**——10 个 agent 同时开就是 25 分钟纯
  等待。**清缓存是全板共享资源的动作，不是「我自己的临时文件」。** 真要清，四步：
  1. `pgrep -fl 'go (build|test|vet)'` —— **有人在编译就不许清**；
  2. `herdr-projects list` —— 板子上有 `working` 的任务就不许清；
  3. **跟人说一声**（在板子的聊天里说一句）；
  4. **优先用小刀代替大锤**：怀疑测试结果脏 → `go clean -testcache`（只让测试结果失效，
     **不动编译产物**）；只是想腾空间 → 先问人。

- **复验用「加压 3 次」，不是「连跑 10 次」。** 这条规矩要的是**堆和 GC 压力**——整包
  10 次挂 3 次、单独跑 0 次，差别就在「整包那些堆和 GC 压力」。`GOGC=10` 直接造那个压力，
  一次顶十次。

- **加压只跑自己改的那几处**（`-run` 过滤），**不要整包跑**。整包 3 次在这台机器上单轮
  就要 62~298 秒，跑的是同一批既有测试，飘的也是那几条固定的，**跟这一票的改动无关**；
  而且同时有几个 agent 在跑的时候机器被占满，测出来的结果本身也不作数。**整包扫描是一次性
  的排查手段，不是每票的验收项。**

- **查布局问题先按 F12**，用框架自带的检查器：元素树、box model、帧耗时、取色器。**别
  先写测试再二分**——那样往往是在测一个猜错了的数，而界面上的位置、间距、颜色，检查器一眼
  就能量出来；量出来的数再写进断言，才是对着**画面**的断言。

- **性能判据只有一条：每帧的分配**（`internal/ui/framebudget_test.go`）。它数的是「这一帧
  建了多少个对象」，**不是**「花了多久」，所以它**不受机器负载影响**——是上面那条禁令
  （不要用固定帧数 / 毫秒当判据）的例外，那条禁令针对的是**时间**类判据。四个界面各有一条
  上限，超了就是真多分配了；上限的注释里写着基线的实测值。**别往那条测试里加时间断言**：
  真窗口一帧多少毫秒跟机器、跟显示器、跟后台负载都有关系，加进去它就在满载的 CI 上飘
  ——而它飘的时候和被测的逻辑一点关系都没有。

- **改完 Go 文件要 `gofmt -w` 你改过的那些文件。** **为什么**：验收命令和 CI
  （`.github/workflows/` 里只有 `windows-aac-spike.yml`）**都不查格式**，`go build` /
  `go vet` / `go test` 也**一条都不查**——所以脏代码能一路合进 main，**没有任何一处会
  报错**：`gofmt` 管的只是空格与对齐，编译照过、测试照过、界面上一个字都看不出来，混在
  别的票里评审也看不出来。**怎么做**：改完一个 Go 文件就 `gofmt -w 那个文件`；收尾前拿
  `gofmt -l 你改的那几个文件` 查一遍，**输出为空**才算完。⚠️ **只跑自己改的那几个**——
  不要整仓 `gofmt -w .`，也不要 `go fmt ./...`（它是按包扫的，会把**别人正在改的文件**
  一起卷进来，把他们的半成品带进你的提交）；也别把跟本次改动无关的排版改动塞进这一票的
  diff——评审就分不清哪些是这一票改的。**看见别的文件也脏**：那是别的票的账，记下来交给
  人另开一票，**别顺手带进你这一票**。

**什么时候用得上**：你在写测试判据、或者一条测试红了你在判断是不是机器忙。

## 已知会飘的那几条

**出处**：`AGENTS.md` §2 的「已知会飘的那几条」名单

（整包跑出来的 FAIL 落在这份名单里的，**不能当回归的证据**；每条后面一句是它为什么飘。）

- `TestTheSearchBoxSaysThreeDifferentThings`——歌词搜索的**异步态**：源那边真睡
  **300ms**，界面这边画一帧就断言「正在搜」，机器一慢那 300ms 先走完，「正在搜」已经不见
  了（2026-10-24 在本票 HEAD 上亲眼见过一次，机器忙的时候）。
- `TestChangingTheDownloadDirectorySaysWhereItTakesEffect`——等的是「改完下载目录之后，
  界面说出它在哪儿生效」，用的是**共用的那个 10 秒**保险丝，机器一慢就超。**低负载下也
  复现过**：2026-10-24 整包跑的一轮里（那一轮 load 最高 7.04），它就是那一句「等了 10s，
  说清楚它在哪儿生效 还没发生」。
- `TestUnfollowingFromTheCardRemovesIt`——「我的关注」那一页的网格**列数要几帧才稳**：
  列数是按**上一帧**量出来的容器宽算的（`followPage.width` → `list.GridColumnsFor`），
  刚出来那一帧先按一个还没量准的宽排成 4 列，下一帧量到真的宽才排成 2 列。**用例在布局
  还没稳的那一帧记住了第二张卡头像的坐标**，于是那一按落在**第一张卡**上——取关取走了
  **另一个人**，而断言「画面上还挂着那个人」就红（实测 2026-10-25 在 load 61 下 30 遍红
  7 遍）。⚠️ **它红的时候不是应用坏了**：应用按的是「指针底下那一枚键」，而那一枚键属于
  指针底下那张卡；是**用例记坐标的那一帧**和**按下去那一帧**布局不同。

### 待低负载复核的一条

（看到它红先别当回归，**也别当定论**。）

- `TestTheQueueDrawerSlideDoesNotAllocatePerFrame`——2026-10-24 在 load 9~21 下整包跑，
  10 轮里飘了 2 次：进场那 12 帧的每帧分配 14.7~15.2，稳态 11.0，超了 **20%** 的余量；
  **单独跑是绿的**（`-run` 过滤 10 次全绿）。那两遍不满足「load 8 以下才作数」，**低负载
  下跑过 20 轮也没复现**，所以它只是「待低负载复核」。

### ⚠️ 「飘」和「一直红」是两回事

这份名单只管**有时红有时绿**的那些。一条**每次都红**的用例是**确定性回归**，**按回归查**
——本仓库有过两条（整包 105 遍全红的 `TestTheDialogButtonsStayOutlined` 和
`TestEveryHandMadePopupHasAShadow`，票 #228/#229），它们当时**不在**名单里才查得出来。
**「在名单里」不等于「不用查」。**

### 曾经记过、现在划掉的两条

`TestTheHoverLayerCoversOnlyTheCover` 和
`TestEveryRouteShowsARealRowOrSaysWhichTicketIsMissing//follow`——2026-10-23 核过：105 遍
整包（load1 12.1~112.5）+ 两条各 50 遍单独跑 + 320 个子测试，**一条没红**；本票又在低负载
下跑了 20 遍，全绿。⚠️ 悬停浮层那条当年的理由（播放键那两个字换图夹在两帧之间）是
**2026-10-21（`f777bc5`）就已经去掉的机制**——那一测现在先把歌按停，而记下它的那次观察在
那道保护之后，所以那个理由从一开始就不成立。**这两条别再往名单里加，除非它们真的红过。**

### 想自己核这份名单

**盯住负载**——一轮整包从头到尾 load 最高不超过 8，那一轮才算数；超了就不算
（`GOGC=10 go test ./internal/ui/ -count=1 -timeout 15m` 一轮一轮往下数）。**别用 `-run`
过滤**——这几条**单独跑都是绿的**，飘的是整包那些堆和 GC 压力。

### 压出来的是别的用例飘红

→ 那是既有问题，**不要顺手修**，记下来交给人另开一票。

**什么时候用得上**：一条界面测试红了，你在判断「这是回归还是飘」。

## 完整的验收命令（两份）

**出处**：`AGENTS.md` §1 与 §2 末尾那段命令

```sh
go build -trimpath -p 4 ./... && go vet -trimpath -p 4 ./... && go test -p 4 \
    $(go list ./... | grep -v '/internal/ui$')   # 默认一次，不跑界面整包
GOGC=10 go test ./internal/ui/ -count=3 -timeout 5m \
    -run '你这次改动对应的用例名'   # 改了界面行为才加
```

**什么时候用得上**：你要跑验收时。
